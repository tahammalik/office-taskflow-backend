# Taskio

Taskio is a REST API for team-based task management. Teams belong to workspaces, workspaces are isolated from each other, and users have roles that control what they're allowed to do.

Built with FastAPI, PostgreSQL, and Redis, using async/await throughout.

## What it does

- **Authentication** — signup, login, logout, and JWT access/refresh token rotation with cookies
- **Workspaces** — create/delete workspaces, add or remove members, each workspace's data stays separate from others
- **Teams** — group users into teams, assign a team leader
- **Projects** — track project status through stages: planning → active → on_hold → review → completed → archived
- **Tasks** — assign tasks to users, track status, keep a history of changes with comments
- **Roles** — three levels (Admin, Manager, User), each with different permissions on what endpoints they can access

## Tech stack

| Piece | What's used | Why |
|---|---|---|
| Framework | FastAPI | Async support, built-in request validation, auto-generated docs |
| Database | PostgreSQL | Relational data (users, workspaces, tasks all reference each other) |
| ORM | SQLAlchemy (async) + asyncpg | Talk to the database without writing raw SQL everywhere |
| Cache/sessions | Redis | Store refresh token state for rotation and revocation |
| Auth | JWT (access + refresh tokens) | Access token is short-lived, refresh token rotates on use |
| Passwords | Argon2 with pepper | Argon2 is a modern, memory-hard hashing algorithm; pepper adds a server-side secret on top of the per-user salt |
| Containerization | Docker + Docker Compose | Run the API, Postgres, and Redis together with one command |

## How authentication works

1. User logs in with username/password → gets an **access token** (short-lived, used for normal requests) and a **refresh token** (stored in an HTTP-only cookie)
2. When the access token expires, the client calls `/refresh` with the refresh token cookie
3. The old refresh token gets checked and revoked, and a **new** access + refresh token pair is issued (this is called token rotation — it means a stolen refresh token can only be used once before it's invalid)
4. Logging out revokes the refresh token so it can't be reused

## Project structure

```
taskio/
├── app/
│   ├── api/v1/          # Route handlers (auth, workspaces, teams, projects, tasks)
│   ├── core/             # Config, database connection, security functions, Redis client, logging
│   ├── models/           # SQLAlchemy database models
│   ├── schemas/          # Pydantic request/response schemas
│   ├── services/         # Business logic that routes call into
│   └── main.py           # App entry point
├── docker-compose.yml
├── Dockerfile
├── requirements.txt
└── .env.example          # Copy this to .env and fill in real values
```

## Running it locally

1. Clone the repo
2. Copy the environment templates and fill in your own values:
   ```bash
   cp .env.example .env
   cp .key.example .key
   ```
3. Start everything with Docker Compose:
   ```bash
   docker compose up --build
   ```
4. The API will be running at `http://localhost:8000`
5. Interactive API docs (auto-generated by FastAPI) are at `http://localhost:8000/docs`

## Roles and permissions

| Role | Can do |
|---|---|
| Admin | Everything — create/delete workspaces, manage all members, manage all projects/teams/tasks |
| Manager | Manage projects and teams within their workspace, assign tasks |
| User | View and update their own assigned tasks |
